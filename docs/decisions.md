# hearth · decisions

Every design decision with its recommendation, reason and status. A decided row keeps its date; an open row is a question for the owner. As of 2026-10-19 every row is decided; new questions are appended with the next free ID. This file is the only place a decision is recorded; other documents describe the result.

| ID | Question | Recommendation | Why | Status |
|---|---|---|---|---|
| D1 | Go core + Swift UI, or pure Swift? | Go core | Reuses llm and shhh's agent, meter, memory, skill, secret packages; keeps provider behaviour identical across the two apps. Pure Swift is cleaner to ship but duplicates that work. | decided 2026-10-19: Go core; Swift is a thin client with no business state |
| D2 | Helper subprocess vs linked library | Subprocess | Crash isolation, no cgo, testable from a CLI, portable contract. | decided 2026-10-19: bundled subprocess |
| D3 | Connect-RPC vs JSON-RPC over the socket | Connect-RPC with a proto contract | Generated Swift client, streaming built in. Fall back to JSON-RPC if the Swift toolchain is heavy, keeping the proto as the message schema. | decided 2026-10-19: Connect-RPC with a proto contract; transport (Unix socket via Network.framework/NIO, else loopback TCP with a per-launch token, Ollama-style) settled in spike 0.1 because URLSession cannot use Unix sockets |
| D4 | Single repo (Go at root, `App/` Xcode) vs two repos | Single repo | They ship as one bundle and version together. | decided 2026-10-19: single repo |
| D5 | Developer ID + Sparkle first; App Store later as a reduced SKU | Yes | Shortcuts execution, folder access and any future Mail path need the non-sandboxed build. | decided 2026-10-19: Developer ID + notarisation + Sparkle; App Store only as a later reduced SKU |
| D6 | Licence | MIT (or Apache-2.0) | Keeps the App Store option open; satisfies OpenAI's open-source programme. GPL-family conflicts with App Store terms. | decided 2026-10-19: MIT |
| D7 | Minimum macOS 26, Apple Silicon only | Yes | Foundation Models, Liquid Glass, App Intents; Intel costs a second architecture for a shrinking base. | decided 2026-10-19: macOS 26+, Apple Silicon |
| D8 | Extract shhh's generic packages into a shared module (beside llm) or copy them into hearth | Extract into a new module (e.g. `rfizzle/agentcore`) in a later step; copy first to unblock M0 | Extraction touches shhh's gates; copying now and extracting once hearth's needs are known avoids designing the seam blind. | decided 2026-10-19: extract the shared module from shhh FIRST (against the recommendation to copy); it is M0 item 0.6 and gates the agent loop work |
| D9 | Should bots run with the app quit (LaunchAgent)? | No in v1; menu bar extra counts as "open" | Grok Bot's cloud persistence is its strongest consumer feature, so this will come up. Decide after M3 with usage data. | decided 2026-10-19: app or menu bar extra open only; revisit a LaunchAgent after M3 |
| Q1 | Name "hearth": keep for the product and bundle id? Check trademark and App Store name availability. | Keep as the working name; check before M5 | | decided 2026-10-19: keep "hearth"; check availability before M5 |
| Q2 | Team channel semantics: lead answers (proposed) vs Grok-style "bots decide who responds" | Lead answers; @mention for a direct member reply | Keeps one owner per thread, avoids duplicate work that both xAI's docs and Anthropic's post report. | decided 2026-10-19: lead answers; @mention for a direct member reply |
| Q3 | Depth: Chief of Staff → lead → member, members cannot delegate | Yes | Bounded by construction. | decided 2026-10-19: yes |
| Q4 | Default concurrency limit and default caps (25 steps, 10 minutes, cost per task) | Start with these; make them org settings under Advanced | Need real usage to tune. | decided 2026-10-19: 25 steps, 10 minutes, per-task cost cap; org settings under Advanced |
| Q5 | Providers at launch | ChatGPT plan, Anthropic key, Gemini key, OpenRouter key, Compatible endpoint | Anthropic and Google forbid subscription sign-in from third-party apps, so keys are the only path there. | decided 2026-10-19: all five plus Apple on-device |
| Q6 | Web search backend | Provider-native search where available (OpenAI, Anthropic, Gemini tools), else a configurable search API key | Avoid a hearth-run search service. | decided 2026-10-19: provider-native search where it exists; optional search API key as fallback; no key, no search tool |
| Q7 | UI vocabulary: "Chief of Staff", "Team", "Task", "Access", "Usage", and no word "bot" | As listed in `model.md#vocabulary-user-facing` | | decided 2026-10-19: as listed in model.md#vocabulary-user-facing |
| Q8 | Composer: ↩ sends (Messages style) or ⌘↩ sends (Slack style) | ↩ sends, ⇧↩ newline | Matches Messages for a consumer audience. | decided 2026-10-19: Return sends, Shift-Return newline |
| Q9 | Should a bot be able to edit its own Notes freely, or only via a visible `remember` call? | Visible call only, owner can edit | Trust through visibility. | decided 2026-10-19: visible `remember` call only; owner edits |
| Q10 | Starter orgs: which three ship, and which role templates (first list: Chief of Staff, Research Lead, Analyst, Writer, Editor, Scheduler, Planner, Reading Digest, Travel Planner, Household Admin) | Ship Solo, Personal office, Small business; 10 templates | Needs a product pass on job descriptions. | decided 2026-10-19: Solo, Personal office, Small business; ten templates as listed |
| Q11 | Where does the Hearth folder default live: `~/Documents/Hearth` or iCloud Drive? | `~/Documents/Hearth`, user may move it | iCloud eviction complicates reads. | decided 2026-10-19: ~/Documents/Hearth, movable |
| Q12 | Cost display currency and whether to show tokens at all on the main path | Currency only; tokens under a disclosure | | decided 2026-10-19: currency only; tokens under a disclosure |
| Q13 | Is a bot a security boundary for *credentials* (e.g. a Shortcut that signs into a service)? | Yes: Shortcuts are granted per bot; no bot sees another's grants | Direct response to Grok Bot's shared-computer criticism. | decided 2026-10-19: yes, per-bot credential boundary |
