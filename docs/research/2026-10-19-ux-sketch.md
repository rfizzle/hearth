# 06 · User experience

> Initial UX sketch from 2026-10-19: information architecture, key flows, empty states, reference apps. Superseded by the app and the gallery as they exist; kept for the reasoning.

Status: draft, 2026-10-19. This describes the shape of the app, not pixels. Visual design follows in `design/` once the structure is agreed.

## 1. Information architecture

One main window, three columns, like Mail or Slack on the Mac.

```
┌──────────────┬──────────────────────────────────┬──────────────────┐
│ Sidebar      │ Conversation                     │ Inspector        │
│              │                                  │ (toggle, ⌥⌘I)    │
│ ★ Chief of   │  messages, task cards, tool cards│  bot/team/task   │
│   Staff      │                                  │  details, Access,│
│ ▸ Inbox (3)  │                                  │  Notes, files,   │
│              │                                  │  usage           │
│ TEAMS        │                                  │                  │
│  Research    │                                  │                  │
│   · Lead     │                                  │                  │
│   · Analyst  │                                  │                  │
│  Writing     │                                  │                  │
│              │                                  │                  │
│ ORG          │                                  │                  │
│  Scheduler   │                                  │                  │
│              ├──────────────────────────────────┤                  │
│ Handbook     │ compose box (⌘↩ to send)         │                  │
│ Usage        │                                  │                  │
│ Settings     │                                  │                  │
└──────────────┴──────────────────────────────────┴──────────────────┘
```

Sidebar rows:

- **Chief of Staff** at the top; selected by default; the main compose box talks to it.
- **Inbox** with a badge: approvals, questions, finished deliverables, pauses.
- **Teams**, each expandable to its members. Clicking a team opens its channel; clicking a member opens the DM. A working bot shows a subtle activity indicator; a paused one a pause glyph.
- **Org** bots other than the Chief of Staff.
- **Handbook**, **Usage**, **Settings** as plain rows at the bottom (Settings also under the app menu, ⌘,).

Task threads are not sidebar rows. They open inline from a task card ("Show work") as a sheet-like pushed view in the conversation column with a back button, so the hierarchy is always visible: *Research channel → Task: Compare three CRMs → Analyst's work*.

## 3. Key flows

### Onboarding (first launch, under five minutes)
1. Welcome: one sentence and a picture of the org shape.
2. Sign in: "Sign in with ChatGPT" (primary, OAuth in the default browser) or "Use an API key" (Anthropic, Gemini, OpenRouter, Compatible) with a help link. Local models: "I run Ollama or LM Studio" detects localhost endpoints. The app picks tier defaults.
3. Name your org and choose the Hearth folder (default created in Documents).
4. Pick a starter org: *Solo* (Chief of Staff only), *Personal office* (Chief of Staff + Research team of 2 + Writer), *Small business* (adds Admin team: Scheduler, Bookkeeper-as-explainer). Each shows the bots and what they will be allowed to do, with everything outward set to "ask me".
5. Permissions are *not* requested here. Each TCC prompt happens at first use, with a purpose string that names the bot and the task.
6. First message: the compose box is prefilled with a suggestion ("Put together a one-page brief on …"). The user watches the Chief of Staff plan, assign, and return a file.

### Hire a bot
"Add" in the sidebar → sheet: role templates grid (with search) or "Describe the job". Fields: name (suggested), avatar (SF Symbol or emoji or photo), team (or "org-level"), job description (template text, editable), Access (checklist in plain words, defaults from the template, everything outward "ask me"), quality tier. Advanced disclosure: exact model, step cap, cost cap. Done. The bot's DM opens with a short self-introduction and one question it needs answered, if any.

### Assign work
Three ways, all producing the same task card: type to the Chief of Staff; type in a team channel (the lead takes it); or the *Assign* button on any bot's DM, which opens a brief form (goal, deliverable, due) for people who prefer structure. Drag a file onto any of these to attach it.

### Watch work
The task card shows state, elapsed, cost, steps, deliverables. "Show work" opens the thread: brief, every tool call as a collapsed card ("Read 3 files", "Fetched 2 pages", "Asked Analyst to …"), sub-task cards, the result. The owner can type into the thread at any time; the bot sees it at its next boundary.

### Approve
Inbox row and a notification. The card shows the plain-English effect from the tool's describer, the bot and task, and the four decisions. Keyboard: ⌘1 Allow once, ⌘2 Allow for task, ⌘3 Always, ⌘⌫ Deny. Denied with a reason returns the reason to the bot.

### Answer a question
Same card shape, with the bot's suggested answers as buttons plus a text field.

### Receive a deliverable
Inbox row: "Research finished *Compare three CRMs* · 2 files". Quick Look on space, "Show in Finder", "Open", "Reply" (goes to the assigner's thread), "Done" (clears from Inbox).

### Recurring task
From any task card: "Repeat…" → schedule picker (daily/weekly/monthly at a time, "while I'm working" interval). Lives in the team's Inspector and under Settings → Schedules. Missed runs show in Inbox with "Run now".

### Usage
A page with a month picker, a stacked bar per team, a table by bot (cost, steps, tasks), budgets inline-editable with a progress ring. Paused bots and teams show a "Resume with a higher budget" affordance.

### Handbook
A simple page list and a Markdown editor (plain text with live preview, no toolbar beyond bold/italic/list). Each page has a scope chip: Everyone or a team. A meter shows how much of the Fast tier's context the handbook occupies.

### Export / import
File → Export Org… produces `Name.hearthorg`. Opening such a file (double-click, drag onto the app, File → Import) shows a preview of bots, teams and Access, with everything outward reset to "ask me", before importing.

## 4. Conversation surface details

- Messages render as bubbles-free rows with avatar, name, time; the owner's on the right edge as in Messages. Markdown rendered; code in monospace; tables as tables.
- Streaming text appears token by token with a stop button in the compose box.
- Tool cards are collapsed one-liners with an icon and a duration; expandable to arguments and results. File results show a Quick Look thumbnail.
- The composer is an AppKit text view: multi-line, attachments, @mention of a team member in a channel (addresses that member directly for a reply, without creating a task), paste of images and files, ⌘↩ to send, ↩ for newline **[D]**.
- Selection and copy work across messages (AppKit transcript if SwiftUI cannot do this well).
- "Earlier in this conversation" disclosure at the top shows the rolling summary the bot is working from.

## 5. Empty states and errors

- Empty org: the Chief of Staff DM explains in one message what to do and offers two buttons: "Add a team" and "Just ask me something".
- Provider failure: a system row in the thread ("Couldn't reach OpenAI: rate limited, retrying in 20s"); persistent failure gives an Inbox item with "Retry" and "Open Settings".
- Budget pause: a card with the amount, who hit it, and the resume affordance.
- No provider configured: the compose box is replaced by a "Sign in to get started" button.

## 6. Accessibility and platform conventions

- Full keyboard navigation, VoiceOver labels on cards and tool rows, Dynamic Type respected, reduced motion honoured for streaming animations.
- Standard menus: File (New Task, Export Org, Import Org), Edit, View (Inspector, Inbox), Team (Add Team, Add Member, Rename), Window, Help.
- Localisable from day one (String Catalogs); English only at launch.
- Light and dark, Liquid Glass materials in the sidebar and toolbars, system accent colour.

## 7. Reference code

Open-source Swift apps to read for patterns, not to copy wholesale. Check each one's licence before lifting code.

- `jordansinger/SwiftUI-Kit`: catalog of stock SwiftUI controls at their defaults (iOS 17 / Sonoma era). Use it to see what the system control looks like before styling anything; it predates Liquid Glass and shows no app structure.
- `jaywcjlove/awesome-swift-macos-apps`: curated list of open-source Swift Mac apps. Entries to study first:
  - `SidhuK/WardenApp`: native multi-provider AI chat with web search; closest in shape to hearth's conversation surface.
  - `synth-inc/onit`: AI chat sidebar that docks to any app; useful for the menu bar and selection-based flows.
  - `huggingface/chat-macOS`: native chat for open-source models; onboarding and local-model detection.
  - `sozercan/ayna`, `askchorus/chorus`: multi-provider comparison UIs; provider settings patterns.
  - `johnbean393/Sidekick`: chat with a local model over the user's files; folder grants and file attachments.
  - `taikun114/Mocolamma`: Swift app managing an Ollama server; a precedent for wrapping a non-Swift backend process.
