## Grok Bot (xAI) — the nearest precedent

Real product, beta since 2026-08-11. Persistent agents, not persona chatbots.

- **Creation**: "New Bot" with name, label, description, avatar; add from a Marketplace; import from a template link; duplicate; or ask an existing bot to propose a focused bot. Docs advise a small roster and narrow jobs ("Talent Scout", not "General Helper").
- **Durable rules** live in the Description ("never send external messages without approval"); task instructions in messages. Skills can be taught by recorded demonstration; Routines are scheduled or event-triggered (third-party guides).
- **Bots talking**: asynchronous bot-to-bot handoffs visible in the transcript; group chats of 2 to 6 bots where bots decide who responds unless the user @mentions; admins can switch bot messaging off. Docs recommend one owner per stage because parallel handoffs cause duplicate work and noisy updates. Approval requests do not appear in groups. No formal teams or org chart; "Chief of Staff" is a community pattern, not a product feature.
- **Runtime**: each account has a persistent cloud Linux computer; bots keep working with the laptop closed; they sign into sites like a person and hand over the screen for passwords and 2FA. Bundled behind $120–$300/month plans, no spend cap.
- **Criticism** (eesel, cellcog reviews): all bots share one computer and its browser sessions and credentials, and xAI says bots are not a security boundary; a stuck shared computer halted every bot on an account; a six-bot business reportedly used 42% of its weekly allowance on day one; no context meter, no fresh-session control, no per-action audit trail, no model choice, approvals cannot undo completed actions.
- **Praise**: near-zero setup; works on tools with no API; enthusiastic non-technical users.

**What hearth takes**: visible handoffs, narrow jobs, small roster, routines, template import. **What hearth does differently**: local Mac, per-bot access grants as a real boundary, audit trail by construction, budgets and a usage meter, model tiers the user controls, approvals outside group noise, no shared browser sessions. **The gap to acknowledge**: Grok's bots work with the lid closed; hearth v1 runs while the app (or menu bar extra) is open (D9).

## AI-employee products

- **Lindy**: "AI employee", router and manager-over-specialists patterns, a Slack Teammate product; per-step credit billing. Reviewers: built around the agent, not around an employee with a manager and approval rules; advice is to start read-only or draft-only.
- **Relevance AI**: no-code "AI Workforce" of agent teams, large integration library; reviewers say multi-agent flows still need clean processes, test data, monitoring and human approval.
- **Salesforce Agentforce**: admin/developer-oriented, inside Salesforce only; steep learning curve; weeks to months to deploy; unpredictable pricing.
- **Microsoft Frontier Firm**: "agent boss" framing; Copilot Studio agent accounts (preview, 2026-10-15) each with an identity, a human manager, Teams/Outlook presence, memory and schedule; Agent 365 as the control plane. The org-chart analogy with governance first.
- **Zapier Agents, Manus, Dust, Glean, Gemini Enterprise**: only roundups found. Recurring complaints: activity billing hard to forecast; agents that don't end in a finished deliverable (Manus is the exception and is praised for exactly that).

Pattern: role + identity + approval boundaries everywhere; real hierarchy is thin in consumer products; billing opacity and missing audit trails recur.

## Frameworks

- **CrewAI hierarchical**: manager agent with a delegation tool; community reports of the manager failing to see workers, doing the work itself, schema errors; behaviour depends heavily on the manager model.
- **AutoGen / Magentic-One**: orchestrator with a Task Ledger (facts, plan) and a Progress Ledger (reflection, next assignment); re-plans when stalled.
- **LangGraph supervisor**: central supervisor with handoff tools, nested sub-supervisors; the supervisor is a single point of failure.
- **OpenAI Agents SDK**: handoffs transfer control (receiver sees full history unless filtered); `as_tool` runs a specialist as a nested call with structured input and no transfer; guardrails only at chain ends.
- **Claude Code agent teams**: lead + teammates in separate contexts, shared task list, mailboxes; documented limits: no nested teams, status lags, lead stops early or does the work itself, concurrent edits clobber; recommended 3–5 teammates.
- **MAST study** (arXiv 2503.13657): 14 failure modes in three groups (system design, inter-agent misalignment, task verification); failures are mostly design and misalignment, not model weakness.

## Published lessons that hearth's design follows

| Lesson | Source | Where hearth applies it |
|---|---|---|
| Multi-agent costs ~15× a chat; use it only for parallelisable, high-value work | Anthropic research-system post | Chief of Staff answers directly when it can; fan-out only for separable parts (`model.md` orchestration §5) |
| Every brief needs objective, output format, tool guidance, boundaries; the subagent sees nothing else | Anthropic; 2026 handoff write-ups | `assign` schema requires goal/context/deliverable; framing says the assignee sees nothing else (`model.md` orchestration §3.3) |
| Pass references, not transcripts | Anthropic; Cognition | Results return a message plus file paths; no parent history is forwarded |
| Default to one agent; split by context, not by role type; avoid the "telephone game" | Anthropic (when-to-use post); Cognition | Depth cap of 3; no planner/implementer/reviewer chains; starter orgs are small |
| Agents negotiating with each other are fragile; peer chat designs lost ground to one coordinator + ephemeral workers | Cognition; 2026 practitioner posts | No peer-to-peer or upward assignment; runs end at every wait (`model.md` orchestration §2, §3.7) |
| Cap fan-out, turns and tokens up front; explicit done criteria | Consolidated | Budgets flow down; step/time/cost caps; retries capped (`model.md` orchestration §4) |
| Give the user a visible owner per stage and a live status view | Grok docs; Claude agent-teams limits | One task card shape everywhere; "Show work" (`model.md` orchestration §10, ux sketch §3) |
| Verifiers must not self-certify | Anthropic | Leads review against the brief; the owner acknowledges deliverables |
| Evaluate with ~20 realistic queries judged on outcome | Anthropic | Roadmap M5.7 |
| Checkpoint and resume | Anthropic | Runs end at boundaries; tasks persist state; crash → failed with Retry (`model.md` orchestration §9) |

## Native Mac chat apps

- **BoltAI**: global hotkey quick bar, AI commands on selected text in any app, inline mode, screenshot analysis; BYO keys in Keychain plus Ollama/LM Studio; one-time price; complaints about onboarding and a limited trial.
- **MindMac, Enchanted, Msty, Jan, LM Studio, Chatbox**: keys or local models only; none found with provider OAuth sign-in; Mac-integration details (Shortcuts, Services, share, Spotlight) unverified for all of them.

Implication: BYO keys in Keychain is the baseline everyone uses; "Sign in with ChatGPT" would be a visible differentiator for non-technical users; selection-based commands and a hotkey are the proven Mac hooks.
